# 管理员后台、注册选项与智能体权限设计

日期：2026-08-20

## 目标

在现有邀请码管理之外增加独立的管理员后台，让管理员维护注册时可选的姓名和组别，并按普通成员账号限制其可见、可使用的官方智能体。

验收结果：

1. 管理员登录后，可从首页右上角分别进入“管理员后台”和“邀请码管理”。
2. 注册页中的姓名、组别改为两个可自由组合的下拉列表，选项由管理员维护。
3. 管理员可为单个成员保存官方智能体白名单；面板始终同时显示该成员的登录账号和姓名。
4. 未配置过个人权限的成员维持现状，可使用全部官方智能体；保存过个人权限后，只能看见和使用被勾选的智能体。
5. 页面隐藏与服务端授权同时生效，成员不能通过直接链接或直接调用接口绕过限制。

## 范围

### 包含

- 新的独立管理员后台 `/admin`。
- 姓名选项和组别选项的新增、停用、重新启用。
- 注册页读取两个独立选项列表。
- 后端校验注册值来自当前启用选项。
- 普通成员目录和按成员设置官方智能体白名单。
- 首页、聊天、工作流、图片/视频工具和独立智能体 SSO 入口的权限执行。
- 管理员始终拥有全部智能体权限。

### 不包含

- 邀请码管理重做或并入新后台。
- 按组别批量授权、角色模板或权限继承。
- 限制成员自己创建的“我的智能体”。个人智能体继续只归创建者本人。
- 姓名与账号一一绑定。同一个姓名选项允许多个账号选择。
- 导入仓库中现有的固定姓名或固定组别名单。

## 已确认的兼容规则

- 姓名、组别是两份独立列表，可以自由组合。
- 新表初始为空。管理员至少新增一个启用姓名和一个启用组别后，新成员才可注册。
- 现有成员的 `nickname`、`groupName` 原值不变。
- 没有个人权限策略记录的成员默认可使用全部官方智能体。
- 管理员保存过成员权限后，严格按白名单执行；白名单可以为空。
- 恢复默认会删除该成员的个人权限策略，使其重新获得全部官方智能体权限。

## 方案选择

采用关系表方案，不把选项和权限塞入 `SystemSetting` JSON，也不增加组别级权限。

关系表可以明确区分“尚未配置”和“明确配置为空”，支持事务替换授权，并可通过唯一约束防止重复选项和重复授权。组别继承会扩大本次范围，JSON 则会削弱并发更新、校验和查询能力。

## 数据模型

### RegistrationOption

保存管理员维护的注册下拉选项。

- `id`: UUID 主键。
- `kind`: `name` 或 `group`。
- `label`: 去除首尾空格后的显示文字。
- `isActive`: 是否在注册页可选，默认 `true`。
- `createdAt`、`updatedAt`: 审计时间。
- 唯一约束：`kind + label`。
- 索引：`kind + isActive + label`。

选项不做物理删除。停用只影响后续注册，既有成员资料保留原字符串。

### UserBotAccessPolicy

表示某个普通成员已经进入“按白名单授权”模式。

- `id`: UUID 主键。
- `userId`: 唯一外键，删除用户时级联删除。
- `createdAt`、`updatedAt`: 审计时间。
- `permissions`: 对应的 `UserBotPermission` 集合。

不存在策略记录代表默认全部可用。存在策略但没有权限记录代表全部官方智能体均不可用。

### UserBotPermission

保存白名单条目。

- `id`: UUID 主键。
- `policyId`: 权限策略外键，删除策略时级联删除。
- `botKey`: 官方智能体稳定标识。
- `createdAt`: 创建时间。
- 唯一约束：`policyId + botKey`。

权限不直接关联数据库 `Bot.id`。现有官方入口同时包含静态内置智能体和独立工具，使用共享代码目录中的稳定 `botKey` 才能统一管理。

## 官方智能体目录

新增无 React 依赖的共享目录模块，汇总：

- `BUILTIN_BOTS` 中的官方内置智能体。
- 首页中的知识库、文案总控、买家秀、详情图、图片生成、视频工作台等独立工具。

目录项至少包含 `botKey`、名称、分类、入口类型和全局可见状态。后台只允许保存目录中存在的 `botKey`，防止写入任意值。

当前产品层面已经全局隐藏的入口仍保持隐藏；个人授权不能使全局隐藏的功能重新出现。服务端仍使用同一 `botKey` 判断直接访问权限。

## 页面设计

### 首页入口

管理员登录后，首页右上角显示两个独立按钮：

- “管理员后台”进入 `/admin`。
- “邀请码管理”继续进入 `/admin/invite-codes`。

普通成员不显示这两个入口。

### 注册选项页签

管理员后台默认提供“注册选项”和“智能体权限”两个页签。

注册选项页签将姓名、组别分成两列。每列包含新增输入框、添加按钮和现有选项列表。输入自动去除首尾空格，同类重复项返回明确提示。选项可停用或重新启用，停用前二次确认。

### 智能体权限页签

左侧成员列表只显示普通成员，支持按登录账号、姓名、组别搜索。每行同时显示姓名和账号；空姓名显示“未填写姓名”。

右侧编辑面板顶部固定显示：

- 成员姓名。
- 登录账号。
- 所属组别。
- 当前权限状态：“默认全部可用”或“已单独配置”。

下方按分类显示官方智能体复选框，并提供“全选”“清空”“保存权限”“恢复默认全部”。切换成员或离开页面时，如存在未保存改动，浏览器要求确认。

## 注册数据流

1. 登录页切换到注册模式时，请求公开的启用注册选项接口。
2. 前端分别渲染姓名和组别下拉框，不允许自由输入。
3. 任一类别没有启用选项时，禁用注册按钮并提示联系管理员。
4. 注册提交继续包含 `nickname` 和 `groupName` 字段，以减少对现有认证调用方的影响。
5. 后端在消费邀请码和写入用户之前，确认两个值分别存在于启用的 `name`、`group` 选项中。
6. 若选项在页面加载后被管理员停用，注册返回 `REGISTRATION_OPTION_INVALID`，前端提示并重新加载选项。

已有但尚未开通的账号走激活流程时同样执行选项校验。已完成开通的现有账号登录不受影响。

## 权限数据流

### 读取

`/api/auth/me` 返回当前用户的权限摘要：

- 管理员：`mode = all`。
- 普通成员且没有策略：`mode = all`。
- 普通成员且存在策略：`mode = selected`，并返回允许的 `botKeys`。

首页以该摘要过滤官方智能体卡片和空分类。个人智能体不走该过滤器。

### 保存

管理员选择成员并保存时：

1. 服务端验证目标用户存在且不是管理员。
2. 服务端验证所有 `botKey` 均属于官方目录。
3. 在一个数据库事务中创建或保留策略、删除旧权限、写入新权限。
4. 返回规范化后的成员权限状态。

“恢复默认全部”在事务中删除该成员策略及其授权记录。

### 服务端执行

新增统一授权函数，根据用户角色、策略是否存在以及 `botKey` 判断访问。拒绝时抛出状态码 `403`、错误码 `BOT_ACCESS_DENIED`，并在产生积分、会话、消息、生成任务或 SSO 票据之前执行。

至少覆盖：

- 新建会话与发送消息。
- 直接进入官方聊天页面。
- 首页通用聊天入口。
- 图片生成和视频工作台任务入口。
- 知识库、文案总控、买家秀、详情图等独立智能体 SSO 启动入口。
- 工作流启动前的全部步骤检查。

历史会话可以继续显示在历史记录中，但重新发送消息时必须重新校验当前权限。

## API 设计

### 公共注册选项

- `GET /api/registration-options`
  - 返回启用中的姓名、组别数组。
  - 不需要登录。

### 管理员注册选项

- `GET /api/admin/registration-options`
- `POST /api/admin/registration-options`
- `PATCH /api/admin/registration-options/:id`

全部要求管理员身份。`POST` 新增选项，`PATCH` 只修改启用状态，不在本次范围内提供改名。

### 管理员成员权限

- `GET /api/admin/members`
  - 返回普通成员的 `id`、账号、姓名、组别、策略状态和允许的 `botKeys`。
- `PUT /api/admin/members/:id/bot-access`
  - 整体保存该成员白名单。
- `DELETE /api/admin/members/:id/bot-access`
  - 恢复默认全部可用。
- `GET /api/admin/bot-catalog`
  - 返回可管理的官方智能体目录。

## 错误处理

- 同类选项重名：`409 / REGISTRATION_OPTION_EXISTS`。
- 注册值不存在或已停用：`400 / REGISTRATION_OPTION_INVALID`。
- 普通成员访问管理员接口：`403 / FORBIDDEN_ADMIN_ONLY`。
- 目标用户是管理员：`400 / ADMIN_ACCESS_IMMUTABLE`。
- 保存了未知 `botKey`：`400 / INVALID_BOT_KEY`。
- 使用未授权智能体：`403 / BOT_ACCESS_DENIED`。

后台保存失败时保留当前勾选状态和错误提示，不静默回滚界面。权限保存采用事务，数据库中不会出现半套新旧混合记录。

## 数据库上线

更新 `frontend/prisma/schema.prisma` 后，沿用现有启动脚本的显式非破坏性同步方式：部署时设置 `PRISMA_DB_PUSH_ON_START=true`，让 `prisma db push` 创建新表。不得加入 `--accept-data-loss`。

新表不做固定名单种子导入。部署完成后，管理员先添加注册选项，再开放新成员注册。

## 测试策略

实现遵循测试先行。每一组生产代码之前先运行对应的新测试，确认因缺少功能而失败，再写最小实现使其通过。

### 权限单元测试

- 管理员始终允许。
- 普通成员无策略时允许全部官方智能体。
- 普通成员有策略时只允许白名单。
- 空白名单拒绝全部官方智能体。
- 恢复默认后重新允许全部。
- 个人智能体不进入官方白名单判断。
- 未知 `botKey` 不能被管理员保存。

### 注册选项测试

- 只返回启用选项。
- 姓名和组别独立组合。
- 同类重名被拒绝。
- 注册接口拒绝未配置或已停用选项。
- 选项为空时注册页显示阻断提示。
- 现有账号普通登录不要求重新选择。

### 接口与入口测试

- 非管理员不能访问后台 API。
- 成员列表同时返回账号、姓名和组别。
- 保存权限为原子替换。
- 首页过滤未授权卡片。
- 直接链接、会话创建、消息发送和独立工具启动均不能绕过权限。
- 工作流包含未授权步骤时拒绝启动并指出缺少权限的智能体。

### 完成前验证

在 `frontend` 目录运行：

1. 新增和现有的 Node 测试。
2. `npm.cmd run test:startup-safety`。
3. `npm.cmd run lint`。
4. `npm.cmd run build`。
5. `npx.cmd prisma validate` 和 `npx.cmd prisma generate`。

如果当前环境缺少可用 PostgreSQL，仅可说明数据库集成测试未运行，不能把 Prisma 静态验证冒充为真实数据库验证。

## 完成标准

- 三项用户需求均有前端入口、数据持久化和服务端授权支持。
- 现有邀请码页面保持独立且行为不回归。
- 现有成员默认权限和资料保持不变。
- 新成员只能从管理员启用的姓名、组别中选择。
- 未授权成员无法通过页面、直接链接或接口使用受限智能体。
- 管理面板在选择成员后始终清晰显示其账号和姓名。
- 自动化测试、Lint、Prisma 验证和生产构建有新鲜的通过证据，或明确报告真实阻塞项。
